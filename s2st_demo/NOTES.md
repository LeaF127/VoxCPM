# 注意事项与常见问题

## 重要提示 ⚠️

---

### 1. 浏览器麦克风仅在 HTTPS 或 localhost 下可用

**问题**：现代浏览器安全策略限制，麦克风只能在以下环境使用：
- `https://` 开头的 HTTPS 网站
- `http://localhost` 或 `http://127.0.0.1`

**错误示例**：
- `http://192.168.1.100:8080` ❌ 无法使用麦克风
- `http://your-domain.com` ❌ 无法使用麦克风（除非 HTTPS）

**解决方案**：
1. **本地开发/演示**：始终使用 `http://localhost:8080` 访问
2. **局域网演示**：
   - 方案 A：在演示设备上配置 Chrome 启动参数：
     ```
     chrome.exe --unsafely-treat-insecure-origin-as-secure=http://your-ip:8080
     ```
   - 方案 B：使用 HTTPS 证书（如 [mkcert](https://github.com/FiloSottile/mkcert)）
   - 方案 C：使用文件上传方式，避免依赖麦克风
3. **公网部署**：必须配置 HTTPS（使用 Let's Encrypt 等）

---

### 2. MediaRecorder 默认格式可能不是后端期望格式

**问题**：不同浏览器录音格式不同

| 浏览器 | 默认格式 | 采样率 |
|--------|----------|--------|
| Chrome | audio/webm | 48kHz |
| Firefox | audio/ogg | 44.1kHz/48kHz |
| Safari | audio/mp4 或 audio/alac | 44.1kHz |

**后端通常期望**：WAV 格式，16kHz 采样率，单声道

**解决方案**：
代码已实现 `convertToWav()` 函数，自动进行：
1. 格式转换 → WAV
2. 重采样 → 16kHz
3. 降混 → 单声道

如果后端仍报错，检查：
- 后端是否支持 WAV 格式
- 后端期望的采样率是多少（修改 `CONFIG.AUDIO.SAMPLE_RATE`）
- 后端是否需要特定的编码（PCM 16-bit）

---

### 3. 端到端模型延迟较高，前端需给出"处理中"状态

**问题**：端到端语音翻译模型通常需要 2-10 秒处理时间，用户可能以为页面卡死

**解决方案**：
代码已实现：
1. 显示「正在处理中...」状态提示
2. 添加动画效果（脉冲闪烁）
3. 更新文案：「端到端模型可能需要几秒钟」

如需调整超时时间，修改：
```javascript
CONFIG.AUDIO.TIMEOUT = 60000  // 默认 60 秒
```

---

### 4. 音频返回体积较大时要避免一次性阻塞 UI

**问题**：
- 翻译后的音频可能有几 MB 大小
- 如果是 base64 格式，JSON 响应会更大
- 大响应下载可能导致页面短暂无响应

**解决方案**：

**前端已处理**：
- 使用异步 Fetch，不阻塞主线程
- 显示加载状态，避免用户以为卡死

**建议后端优化**：
1. 优先返回音频 URL 而非 base64：
   ```json
   {
     "audio": "http://server.com/static/output.wav"  // 推荐
   }
   ```
   而不是：
   ```json
   {
     "audio": "UklGRiQAAABXQVZFZm10IBAAAAABAAEA..."  // 避免用于大音频
   }
   ```

2. 考虑音频压缩：
   - 使用 MP3 格式而非 WAV（减小 80% 体积）
   - 降低采样率（16kHz → 24kHz 质量差别不大）

3. 使用流式传输（高级）：
   - WebSocket 实时推送音频块
   - Server-Sent Events 边生成边返回

### 5. 文本字段缺失是正常情况，不应视为错误

**问题**：
- 端到端模型的输入输出都是音频
- 中间文本（ASR、MT）可能不存在或难以提取
- 前端不应因为缺少文本字段就报错

**解决方案**：
代码已实现容错处理：
1. 仅当有文本时才显示文本区域
2. 音频字段缺失才会报错
3. 文本缺失时控制台输出提示（而非错误）

**后端返回示例（正常）**：
```json
{
  "audio": "http://server.com/output.wav"
}
```
前端会正常播放音频，不显示文本区域。

### 6. 浏览器自动播放策略可能阻止音频播放

**问题**：
- 现代浏览器阻止自动播放音频
- 用户必须与页面交互后才能播放

**解决方案**：
代码已尝试自动播放，但可能被阻止。

**用户体验建议**：
1. 在演示前提醒用户：「稍后会自动播放翻译结果」
2. 如果自动播放失败，用户手动点击播放按钮即可
3. 添加播放提示：「点击播放器收听翻译结果」

### 7. CORS 跨域问题

**问题**：前端和后端不在同一域时，请求会被浏览器阻止

**错误示例**：
```
Access to fetch at 'http://localhost:8000' from origin 'http://localhost:8080'
has been blocked by CORS policy
```

**解决方案**：

**后端配置（Python Flask）**：
```python
from flask_cors import CORS
CORS(app)
```

**后端配置（FastAPI）**：
```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_methods=["*"],
    allow_headers=["*"],
)
```

**后端配置（通用）**：
返回响应头：
```
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: POST, OPTIONS
Access-Control-Allow-Headers: Content-Type
```

### 8. 不同浏览器对 MediaRecorder 支持差异

**问题**：
- Safari 对 MediaRecorder 支持较晚（iOS 14.5+）
- 某些格式在特定浏览器不支持

**兼容性**：
| 浏览器 | 最低版本 | 支持格式 |
|--------|---------|---------|
| Chrome | 49+ | webm, mp4 |
| Firefox | 25+ | ogg, webm |
| Safari | 14.5+ | mp4 |
| Edge | 79+ | webm, mp4 |

**解决方案**：
1. 代码已做兼容处理，自动选择支持的格式
2. Safari 用户建议使用文件上传方式
3. 演示时推荐使用 Chrome 或 Edge

## 快速故障排查

| 问题 | 可能原因 | 排查步骤 |
|------|---------|---------|
| 麦克风无法启动 | 非 localhost / 权限未授予 | 1. 检查 URL 是否为 localhost<br>2. 查看浏览器是否弹出权限提示<br>3. 检查浏览器设置中的麦克风权限 |
| 录音后无响应 | 后端未启动 / CORS 错误 | 1. 打开 F12 控制台查看错误<br>2. 确认后端服务运行<br>3. 检查 CORS 配置 |
| 音频无法播放 | 返回格式错误 | 1. 检查 Network 面板响应内容<br>2. 确认 audio 字段格式（URL/base64）<br>3. 检查 AUDIO_TYPE 配置 |
| 页面长时间无响应 | 模型处理慢 / 超时 | 1. 增加 TIMEOUT 配置<br>2. 检查后端日志是否在处理<br>3. 考虑使用更短的音频测试 |
| 自动播放被阻止 | 浏览器策略 | 1. 正常现象，手动点击播放<br>2. 演示时先让用户点击页面 |
| 上传大文件失败 | 文件大小超限 | 1. 检查 MAX_FILE_SIZE 配置<br>2. 使用更短的音频 |

## 调试技巧

### 1. 打开浏览器开发者工具（F12）

**Network 面板**：
- 查看请求是否发送成功
- 查看响应状态码和内容
- 查看响应时间（评估模型速度）

**Console 面板**：
- 查看 JavaScript 错误
- 查看自定义的 console.log 输出
- 查看「文本字段缺失」等提示

**Application 面板**：
- 清除缓存（如有需要）
- 查看麦克风权限状态

### 2. 测试后端接口

使用 cURL 或 Postman 直接测试后端：

```bash
# 测试后端是否正常
curl -X POST http://localhost:8000/s2st \
  -F "audio=@test.wav" \
  -v
```

### 3. 使用简单音频文件测试

- 使用 3-5 秒的短音频测试
- 确保音频是标准 WAV 16kHz 格式
- 避免使用有背景噪音的音频
